# Безопасность DL-06

Бот работает с локальными cookies и облачными ключами. Доступ к самому ПК должен
оставаться только у владельца и доверенных системных администраторов.

## Публикация исходников

Перед публикацией запустите `.venv\Scripts\python.exe security_check.py`.
Проверка читает исходники и сравнивает их с локальными значениями токенов, ключей
и cookies; значения секретов в результатах не печатаются. В Git также проверяется
индекс: приватный файл, добавленный через `git add -f`, блокирует проверку.
Публичный список файлов задан в `security_check.py:publication_files`.

`.gitignore` исключает `config.py`, `Token`, `cookies*.txt`, `site_cookies/`,
`r2_config.json`, `cloudflare_analytics.json`, `whitelist.txt`, `_state/`,
скачивания, логи, настройки IDE, архивы и старые копии. Для установки есть
`config.example.py` и JSON-примеры без рабочих ключей.

Не загружайте всю рабочую папку вручную: игнорирование Git не применяется к ZIP,
вложениям и веб-загрузке файлов. Старые бэкапы также могут содержать приватные
данные. Проверка текущих файлов не проверяет историю GitHub или ранее отправленные
архивы. Если секрет уже попал в публичный доступ, его нужно отозвать и заменить;
одного удаления файла недостаточно.

## Сетевые запросы и обработка файлов

- Входящие ссылки ограничены YouTube, SoundCloud, Spotify, Яндекс.Музыкой,
  TikTok и Instagram. Поддомены проверяются по границам доменного имени.
- Для скачивания и поиска используются защищённые HTTP-клиенты. Разрешены только
  HTTP/HTTPS и порты 80/443, без учётных данных в URL. Локальные, служебные,
  зарезервированные и неоднозначные адреса блокируются, включая смешанные ответы DNS.
- Requests соединяется с уже проверенным числовым адресом, сохраняя исходное имя
  для TLS. curl проверяет каждый редирект вручную и закрепляет проверенные IP через
  CURLOPT_RESOLVE. Прокси из окружения отключены у этих клиентов.
- Если VPN возвращает Fake-IP из `198.18.0.0/15`, бот проверяет настоящие адреса
  через Cloudflare DNS over HTTPS. Сам запрос DNS направлен на фиксированные
  публичные IP с проверкой TLS. Для доменов музыкальных/видеосервисов и их CDN из
  явного списка `VPN_HTTPS_DOMAINS` сохраняется существующий маршрут VPN: только
  HTTPS на 443, после проверки публичного DNS и с проверкой TLS-имени сервиса.
  Для остальных хостов используются проверенные публичные IP. Локальные диапазоны
  вроде 127.0.0.0/8 и 192.168.0.0/16 не разрешаются даже для доменов сервисов.
  Прямые ссылки на Fake-IP также запрещены. Это не меняет DNS Windows или VPN.
- FFmpeg обрабатывает локальные файлы с запретом сетевых протоколов. Внешние сетевые
  загрузчики и прямые трансляции не поддерживаются. Это исключает обход проверки
  адресов через резервный загрузчик FFmpeg.
  Разрешены только демультиплексоры медиафайлов: локальные HLS/concat-плейлисты
  не могут заставить FFmpeg читать произвольные соседние файлы.
- Временные файлы изолированы для каждого запроса и удаляются при успехе и ошибке.
  Существующие лимиты размера запроса, диска и R2 сохраняются.

## Доступ и диагностика

Админские команды, кнопки и добавление пользователей проверяют ID администратора
и личный чат. Данные inline-кнопок выбора привязаны к пользователю, чату и сообщению.
Очередь скачивания ограничена; очередь подготовки — не более 8 заданий. На входе
разрешено до 3 ссылок за 15 секунд на пользователя. Уведомления о неизвестном
пользователе ограничены одним за 15 минут, общим пределом 30 за час.

Токены, известные значения cookies, пароли, HTTP-заголовки авторизации и параметры
URL маскируются в диагностике. Облачная ссылка по-прежнему выдаётся получателю,
поскольку она нужна для скачивания. Обладатель этой ссылки может пользоваться ею
до истечения срока или удаления объекта: её нельзя публиковать как обычную ссылку.

Эти меры не заменяют обновления Windows, FFmpeg, Node.js и Python-зависимостей.
Бот продолжает работать с правами текущего пользователя Windows; для дополнительной
изоляции его можно перенести под отдельного пользователя или на отдельную машину.
